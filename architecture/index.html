Inside the reusable agent

The same six-stage loop, specialised at runtime

1

Retrieve

Select the latest and most relevant documents for the company, period and requested metrics.

2

Extract

Capture reported history, management guidance and operating indicators with source citations.

3

Model

Build metric-specific bridges using deterministic formulas and explicit assumptions.

4

Stress

Produce downside, base and upside cases; identify the variables that matter most.

5

Judge

Use model reasoning to select the final scenario and explain conflicts or uncertainty.

6

Return

Emit one strict result object containing forecasts, evidence, calculations and risks.

Prompt architecture

signal_agent/prompts/financial_reports.md

  • Cite every material fact
  • Never invent missing values
  • Preserve requested units

Quality control

The collation layer is a gate, not a copy step

  • All three requested metrics are present and numeric
  • Labels, units and fiscal periods match the challenge specification
  • Latest guidance supersedes older guidance
  • Forecasts reconcile to supporting calculations
  • Implied growth, margins and EPS fall within defensible ranges
  • Every important forecast assumption has supporting evidence
  • Only the intended workbook cells differ from the supplied templates
  • All four workbooks pass the repository submission checker

Fail closed: a malformed or unreconciled result is rejected and retried. It is never silently written into a submission workbook.

Reproducibility

One command, complete evidence trail

Final command

python3 agent/run.py --all

The orchestrator launches four isolated copies of the reusable agent concurrently, injects each company configuration and prompt, validates the results, produces the workbooks and records a timestamped log.

Run artifacts

runs/<timestamp>/

Contains per-company research, result JSON, prompt and model metadata, validation reports, errors and the final execution log.

Known limitations

Where judgement still matters

Disclosure gaps

Companies do not report every quarterly input needed for a clean bridge. The agent must disclose approximations instead of presenting them as facts.

Model sensitivity

Scenario selection can vary when evidence is ambiguous. Deterministic calculations and explicit scenario bounds limit the impact.

Time and API failures

Parallel execution reduces runtime, while isolated outputs and targeted retries prevent one failed company from corrupting the run.
